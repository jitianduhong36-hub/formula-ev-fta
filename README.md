# Formula EV FTA Lab

学生フォーミュラEV向けの静的FTAアプリ。個人用は外部サービス・依存ライブラリ・ログイン不要。共同編集はSupabaseの共有ルームを使用します。

## 利用
`npm start` → http://127.0.0.1:4173 。`npm test` で計算エンジンを検証。

ノードを選択し名称・種類・確率・子事象を編集します。追加した事象は親ゲートの子事象として選択してください。同じIDを複数の枝から参照すると共通原因になります。JSON保存・読込でモデルを共有でき、図をSVG/PNGで出力できます。変更はlocalStorageに自動保存されます。ブラウザーのデータ削除に備えてJSONを保管してください。公開URLはアプリのみを共有し、ユーザーの解析データを送信しません。

## 計算
AND/ORの単調ブール論理を縮約BDDで評価します。基本事象IDごとに一度だけ確率を割り当てるため、繰り返し事象・共通原因の重複を扱います。異なる基本事象IDは独立です。任意の相関・NOT・時系列故障は非対応。共通原因は独立した基本事象としてモデルに明示してください。確率の評価期間と条件を揃えてください。サンプルの確率は架空の例示値です。

最小カットセットは集合の和積と吸収則で求めます。表示確率は集合内の積で、カットセットの単純和はトップ事象確率ではありません。

Birnbaum = Q(p_i=1)-Q(p_i=0)、FV = [Q-Q(p_i=0)]/Q、RAW = Q(p_i=1)/Q、RRW = Q/Q(p_i=0)。分母0は「—」。計算は倍精度浮動小数点。最大300ノード、BDD約60,000ノード、最小カットセット5,000件、中間展開100,000件ほか処理上限があり、超過を表示します。

## GitHub Pages
公開リポジトリの Settings → Pages → Source を GitHub Actions にします。mainへのpushでテスト後に静的ファイルを公開します。[GitHub公式手順](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。リポジトリ作成・Pages有効化には所有者権限が必要です。Actionsには contents:read、pages:write、id-token:write を使用します。

## 検証
共通原因 `(A∧B)∨(A∧C)`、吸収則、0/1確率、不正入力、70個のランダムDAGと全状態列挙の一致・カットセット最小性を検証します。

## 共同編集
「共有ルームを作成」すると現在のモデルをSupabaseに保存し、編集キー付きの共有リンクを発行します。メンバーは同じリンクを開いて編集します。通常約2秒で更新されます（1.5秒間隔のポーリング）。キーはURLのフラグメントに入り、GitHub PagesへのHTTPリクエストには含まれません。リンクを知る全員が閲覧・編集できます。ユーザーごとの権限管理・キー失効・履歴は未対応です。新しいルームの作成で別モデルとして共有できます。

各変更はリビジョン比較を伴うDBトランザクションで保存します。古いリビジョンからの書き込みは拒否し、クライアントで3方向マージします。別ノード・別項目の変更は統合し、同じ項目の変更、編集と削除、マージで生じた循環などは競合として表示します。競合時はローカル内容をJSON保存でき、共有の最新版を読み込んで再編集します。入力中のフォームは他人の更新で置換しません。「変更を反映」で同期対象になります。

通信断時は端末内コピーを保持し自動再試行します。再読込時に以前の端末内コピーと共有版が異なる場合は、以前の内容をJSON出力できます。個人用モデルは共有データとは別の保存領域です。未同期の内容はJSONでバックアップしてください。

`collaboration-config.js` はブラウザー公開用URL・publishable keyのみを含みます。DB用の秘密キーは含めません。DB設定は `supabase.sql`。テーブルはRLS有効・直接権限なし。匿名RPCが256-bit編集キーのSHA-256ハッシュを照合します。作成・読込・更新のみが公開されています。解析ルームを列挙するAPIはありません。

## 新規シート・保存状態・受信確認
上部の「＋新規シート」からトップ事象1つの空のモデルを作成します。保存先はクラウドが初期選択です。元のモデルは残ります。「選択事象の下に原因を追加」で接続した基本事象／AND／ORゲートを作れます。基本事象の親へ初めて追加した場合は親をORへ変換します。新規事象の確率0は仮置きです。

詳しい手順とFAQは `guide.html` に収録。「シート一覧」は端末内のリンク集であり、アカウント単位のクラウド一覧ではありません。クラウドのモデル本体は同じ共有リンクで別端末からも開けます。

保存状態は入力中、送信待ち、クラウド保存済みr番号、競合を表示します。最終クラウド確認はこの画面で通信できた時刻です。`presence.sql` のキー検証付きRPCで、参加画面が約3秒ごとに受信版と編集状態を報告します。30秒以内の画面を接続中と数えます。受信済みは画面による取得で、人による既読や承認ではありません。表示名は自己申告です。モデルの保存と受信確認は別です。

## 接続・削除の操作改善
図の線をクリック、または選択事象の接続一覧から線だけを外せます。事象は残ります。既存事象の接続、移動元・移動先を選ぶつなぎ直しも確認画面付きです。循環を拒否します。最後の子を外す場合は親を確率0の仮置き基本事象へ変換し、警告します。

事象の削除は「この事象だけ」「専用の下位原因も」の2方式です。後者は外部の枝で参照される共通原因とその下の原因を保護します。削除対象・保護対象・影響を確定前に表示します。トップ事象は削除不可です。子事象の選択はチェック式です。

元に戻す・やり直すはこの画面の30操作を保持します。再読込または他人の変更の取込みでクリアします。共有シートでは元に戻す内容も同期します。操作確認中にモデルが変化した場合は再確認を要求します。詳細手順はguide.html参照。

## Google DriveのJSONコピー
本体はSupabaseに残し、Driveへ非同期のJSONコピーを保存します。新規クラウドシートのINSERTで待ち行列へ登録し、登録済みシートの更新で要求版を進めます。既存シートは自動で一括登録せず、編集キー付きの登録操作を必要とします。

Drive保存先は11zncejxIxqCL_KQ3NVhNfIaVGV-3nC8t。所有者の管理用Apps Scriptを初回承認すると1分間隔のトリガーで処理します。google-drive-sync.gsは秘密キーを含まないテンプレートです。管理キーは公開GitHubやフロントエンドへ入れず、非公開Apps ScriptのScriptPropertiesへ保存します。DBにはSHA-256のみを保存します。キーはFTAの保存待ち読込・完了報告にのみ使用し、Googleの認証情報はSupabaseへ渡しません。

drive-sync.sqlの待ち行列はprivate schema内、直接権限なし。リースで重複処理を防ぎ、古い完了報告を拒否し、新しい要求版を保持します。JSON作成後の応答失敗はファイルID・descriptionで再利用します。Googleで移動・ゴミ箱へ入れたファイルを勝手に作り直しません。失敗は待ち時間を増やして再試行します。Driveファイルの編集をSupabaseへ戻す双方向同期は非対応です。


## FTA→FMEA下書き（仮機能 0.1）
「FMEA生成（仮）」で現在のトップを対象に生成します。FTA起点のFMEA下書き。網羅性・故障モードの妥当性・検出手段は人が確認すること。

|FTAの情報|FMEAへの転用|
|---|---|
|BASICのlabel|故障モード候補。人が編集|
|親ゲート|局所的影響。ANDの他の子を条件として併記|
|トップまでの全経路|上位・最終影響。経路は200件/行・全体3000件で明示的に一部省略|
|次数1の最小カットセット|単一故障点（FTAモデル上）|
|pとmission|暫定O採点の根拠。故障率λへの換算はしない|
|色グループ|参考分類。実在の部品とは認定しない|

基本事象×明示対象トップで1行。共有IDの複数経路は同じ行へ集約します。親がORだけでは単独到達と判定せず、最小カットセットを利用します。次数2以上のみなら他の基本事象の条件を最大5件（残り件数も表示）と「冗長性喪失/劣化の候補・実機要確認」を出力。カットセット計算の上限時は「未確定(上限到達)」。論理に吸収される事象も行を残して要確認表示します。

設定は fmea-config.js。ユーザー要件書の暫定O基準（0.1→10、0.01→8、0.001→6、0.0001→4、0.00001→2、それ未満の正の値→1）を採用し、規格の基準とは主張しません。p=0は未採点。Sはトップ設定、Dは空欄。全て1〜10の整数が揃う場合だけRPNを算出。行のS/O上書きは手入力と表示します。Sの点数定義はチームで定めてください。APは対象外。

手入力は任意の fmea オブジェクト（schema:1、topSeverity、targetIds、parts、rows）にだけ保持。1項目500文字、部品500件。自動O/RPN・経路・カットセット全文は保存しません。行IDは各IDをURLエンコードした FM:{basic}@{top}。確認済みは関連するFTA構造・基本事象確率・名称・カットセット等のSHA-256を記録し、変更時に再確認と表示します。削除・対象変更で孤立した手入力は手動で削除するまで残ります。共同編集は行ID・項目単位、部品は部品ID単位でマージし、同一項目の同時変更は競合です。

部品CSVテンプレートの基本列は部品ID/名称/サブシステム/機能。任意の「基本事象ID（JSON配列）」列で明示対応を入力できます。CSV読込はIDで追加・更新。名称類似で対応付けしません。「判定不可」「FMEA未カバー」「トップ未接続」「関連事象あり・故障モード網羅性は未確認」の4状態を出します。

CSVはBOM付きUTF-8でFMEA表のみ。ExcelはFMEA、経路詳細、カットセット、網羅性ギャップ、採点根拠の5シートです。外部通信・ライブラリ・ビルド不要の最小OOXML/ZIP書き出し（fmea-export.js）。文字列はインライン文字列、任意の数式は取り込みません。RPNのみ制御された数式で、S/O/Dの未入力・不正値は空欄。CSVの数式開始文字はエスケープします。生成済みExcelの編集をアプリへ逆輸入する機能はありません。

## 保存容量（2MiB・300事象）
旧200,000バイトはこのアプリ独自の上限で、Supabaseの固定上限ではありません。storage-limits.sqlで既存の検証関数だけを置き換え、1シート2,097,152バイト・300事象へ拡張。新規環境はsupabase.sqlにも反映済みです。API権限や共有範囲は変更しません。JSON読込も2MiB、モデルはUTF-8の整形JSONサイズで保守的に検査。DBではjsonbテキストのバイト数を検査。旧200KB超過と85%以上を表示し、上限超過は送信前に拒否してフォームを保持します。ブラウザーのlocalStorage総容量は別の制約で、保存不能時は通知するためJSON保存を利用してください。Supabaseプラン全体の容量を増やす操作ではなく、シート数に応じた総容量は別途管理が必要です。

既知の制約：経路上限時は詳細が一部省略されます。基本事象が既に故障原因を表す場合は故障モードの妥当性を人が修正する必要があります。FTAに無い部品・故障モードは自動生成されません。出力・画面の確認済みは専門家による安全性保証を意味しません。

## 表示IDと系統
`code`（表示ID、シート内一意）と`system`（系統コード）は任意のノード属性。内部`id`は接続・共通事象・FMEA行の安定キーとして維持する。系統候補・採番は`event-codes.js`。旧JSONは変更なしで読める。表示ID変更は`id`の改名ではない。検索は日本語・英語の系統別名も対象。並行採番による同名コードはマージ検証で競合にする。詳細は操作ガイド参照。
