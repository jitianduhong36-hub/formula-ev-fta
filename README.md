# Formula EV FTA Lab

学生フォーミュラEV向けの静的FTAアプリ。個人用は外部サービス・依存ライブラリ・ログイン不要。共同編集はSupabaseの共有ルームを使用します。

## 利用
`npm start` → http://127.0.0.1:4173 。`npm test` で計算エンジンを検証。

ノードを選択し名称・種類・確率・子事象を編集します。追加した事象は親ゲートの子事象として選択してください。同じIDを複数の枝から参照すると共通原因になります。JSON保存・読込でモデルを共有でき、図をSVG/PNGで出力できます。変更はlocalStorageに自動保存されます。ブラウザーのデータ削除に備えてJSONを保管してください。公開URLはアプリのみを共有し、ユーザーの解析データを送信しません。

## 計算
AND/ORの単調ブール論理を縮約BDDで評価します。基本事象IDごとに一度だけ確率を割り当てるため、繰り返し事象・共通原因の重複を扱います。異なる基本事象IDは独立です。任意の相関・NOT・時系列故障は非対応。共通原因は独立した基本事象としてモデルに明示してください。確率の評価期間と条件を揃えてください。サンプルの確率は架空の例示値です。

最小カットセットは集合の和積と吸収則で求めます。表示確率は集合内の積で、カットセットの単純和はトップ事象確率ではありません。

Birnbaum = Q(p_i=1)-Q(p_i=0)、FV = [Q-Q(p_i=0)]/Q、RAW = Q(p_i=1)/Q、RRW = Q/Q(p_i=0)。分母0は「—」。計算は倍精度浮動小数点。最大150ノード、BDD約60,000ノード、最小カットセット5,000件、中間展開100,000件ほか処理上限があり、超過を表示します。

## GitHub Pages
公開リポジトリの Settings → Pages → Source を GitHub Actions にします。mainへのpushでテスト後に静的ファイルを公開します。[GitHub公式手順](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。リポジトリ作成・Pages有効化には所有者権限が必要です。Actionsには contents:read、pages:write、id-token:write を使用します。

## 検証
共通原因 `(A∧B)∨(A∧C)`、吸収則、0/1確率、不正入力、70個のランダムDAGと全状態列挙の一致・カットセット最小性を検証します。

## 共同編集
「共有ルームを作成」すると現在のモデルをSupabaseに保存し、編集キー付きの共有リンクを発行します。メンバーは同じリンクを開いて編集します。通常約2秒で更新されます（1.5秒間隔のポーリング）。キーはURLのフラグメントに入り、GitHub PagesへのHTTPリクエストには含まれません。リンクを知る全員が閲覧・編集できます。ユーザーごとの権限管理・キー失効・履歴は未対応です。新しいルームの作成で別モデルとして共有できます。

各変更はリビジョン比較を伴うDBトランザクションで保存します。古いリビジョンからの書き込みは拒否し、クライアントで3方向マージします。別ノード・別項目の変更は統合し、同じ項目の変更、編集と削除、マージで生じた循環などは競合として表示します。競合時はローカル内容をJSON保存でき、共有の最新版を読み込んで再編集します。入力中のフォームは他人の更新で置換しません。「変更を反映」で同期対象になります。

通信断時は端末内コピーを保持し自動再試行します。再読込時に以前の端末内コピーと共有版が異なる場合は、以前の内容をJSON出力できます。個人用モデルは共有データとは別の保存領域です。未同期の内容はJSONでバックアップしてください。

`collaboration-config.js` はブラウザー公開用URL・publishable keyのみを含みます。DB用の秘密キーは含めません。DB設定は `supabase.sql`。テーブルはRLS有効・直接権限なし。匿名RPCが256-bit編集キーのSHA-256ハッシュを照合します。作成・読込・更新のみが公開されています。解析ルームを列挙するAPIはありません。

## 新規シート・保存状態・受信確認
上部の「＋新規シート」からトップ事象1つの空のモデルを作成します。保存先はクラウドが初期選択です。元のモデルは残ります。「選択事象の下に原因を追加」で接続した基本事象／AND／ORゲートを作れます。基本事象の親へ初めて追加した場合は親をORへ変換します。新規事象の確率0は仮置きです。

詳しい手順とFAQは `guide.html` に収録。「シート一覧」は端末内のリンク集であり、アカウント単位のクラウド一覧ではありません。クラウドのモデル本体は同じ共有リンクで別端末からも開けます。

保存状態は入力中、送信待ち、クラウド保存済みr番号、競合を表示します。最終クラウド確認はこの画面で通信できた時刻です。`presence.sql` のキー検証付きRPCで、参加画面が約3秒ごとに受信版と編集状態を報告します。30秒以内の画面を接続中と数えます。受信済みは画面による取得で、人による既読や承認ではありません。表示名は自己申告です。モデルの保存と受信確認は別です。

## 接続・削除の操作改善
図の線をクリック、または選択事象の接続一覧から線だけを外せます。事象は残ります。既存事象の接続、移動元・移動先を選ぶつなぎ直しも確認画面付きです。循環を拒否します。最後の子を外す場合は親を確率0の仮置き基本事象へ変換し、警告します。

事象の削除は「この事象だけ」「専用の下位原因も」の2方式です。後者は外部の枝で参照される共通原因とその下の原因を保護します。削除対象・保護対象・影響を確定前に表示します。トップ事象は削除不可です。子事象の選択はチェック式です。

元に戻す・やり直すはこの画面の30操作を保持します。再読込または他人の変更の取込みでクリアします。共有シートでは元に戻す内容も同期します。操作確認中にモデルが変化した場合は再確認を要求します。詳細手順はguide.html参照。
